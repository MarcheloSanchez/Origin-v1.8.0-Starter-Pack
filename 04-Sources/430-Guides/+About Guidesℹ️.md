# About Guides

> [!tip]+ **⚡ Quick Reference**
> **What**: Step-by-step instructions, best practices, and reference manuals for recurring tasks and complex workflows  
> **Why**: Reduce cognitive load, standardize quality, and accelerate execution by reusing proven procedures  
> **How**: Identify → Document → Refine → Apply → Update → Teach  
> **When**: Create after mastering a task; review quarterly for accuracy  
> **Where**: 450-Reference/Guides, linked from Tools, Efforts, and Workflows  
> **Success**: Faster task completion, fewer errors, easier knowledge transfer  
>
> **📖 Next Action**: Capture one frequently repeated process using [[New Guide Auto]]

---

## 🎯 What Guides Are

> [!abstract]+ **Your Operational Playbooks**
> Guides convert tacit know-how into explicit, reusable playbooks. They cover everything from software setup (e.g., “git user guide”) to strategic processes (e.g., “Choosing system”). Each guide answers: *What, Why, When, How, and Who*.
>
> **Not Blog Posts** – Guides are living documents refined through use  
> **Not Checklists** – Guides provide context, rationale, and troubleshooting alongside steps

## 🩺 Guide Quality Diagnostics

**🔴 Fix Now**  
- Outdated steps after tool update  
- Missing screenshots / code snippets  
- No troubleshooting section  

**🟡 Improve Soon**  
- Walls of text → needs headings & bullets  
- Lacks rationale for each step  
- No links to related Tools/Efforts  

**🟢 Excellent**  
- Clear purpose, prerequisites, steps, checks  
- Updated within last 6 months  
- Linked from relevant workflows and Tools  

---

## 🔮 Guide Evolution Patterns

1. **Draft** – Rough notes captured during task execution  
2. **v1.0** – First polished version with full steps & screenshots  
3. **Living Guide** – Updated after every significant change (plugin update, new best practice)  
4. **Playbook** – Mature guide referenced by multiple people/teams; includes FAQs and troubleshooting  
5. **Automation Candidate** – Steps stable enough to script via Templater or shell scripts  

---

## 🔄 Guide Maintenance Workflow

1. **Capture**: Write rough steps while performing task  
2. **Polish**: Add context, expected results, pitfalls  
3. **Link**: Connect to Tools, Efforts, Areas, and Dashboard  
4. **Review (Quarterly)**: Verify accuracy, remove obsolete info, add improvements  
5. **Version**: Update header `modified` date; log major changes in Changelog  
6. **Promote**: Share in team channel or publish externally when mature  

---

## 🎯 Guide Philosophy

> **“Document once, benefit forever.”**  
>  • *Clarity*: Write for future-you under time pressure  
>  • *Context*: Explain *why* each step matters  
>  • *Continuity*: Keep guides alive with regular reviews  
>  • *Connection*: Link guides to workflows, tools, and teaching moments

## 🚀 Getting Started

**Week 1**  
- List 5 recurring tasks that cause friction  
- Draft one guide each day using [[New Guide Auto]]  

**Week 2–4**  
- Polish drafts with screenshots & troubleshooting  
- Link each guide from relevant Tool and Effort notes  
- Set quarterly reminder in Calendar for guide review  

**Month 2+**  
- Automate stable guides with scripts  
- Share mature guides with peers; gather feedback  
- Track time saved to quantify guide ROI
